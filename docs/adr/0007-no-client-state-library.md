# No client state library: server data is pushed live, or read once

The web app keeps no client copy of server data beyond "the latest view" in the component that shows it. Anything that changes while a page is open is a whole view pushed over Server-Sent Events (`useLive`); anything read once goes through `useFetch`; changes go out with `request()` / `call()` and come back through the stream. Only `lib/` talks to the server, which the linter enforces. Zustand, Jotai, context stores and TanStack Query were weighed (`.scratch/state-library/analysis.md`): client state is small and local, every navigation is a full page load, and a query cache would add a second model for server data next to the live views. Revisit if pages start keeping state across navigation, or the client gets shared state the server doesn't know about.
